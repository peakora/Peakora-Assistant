# Registry  -  Skills & Agents Master Index

This is the single source of truth for what every skill and agent in the hub
does,and **which to choose when two overlap**. The overlap rules below are
the resolution policy  -  the agent follows them instead of guessing on the fly.

Updated: 2026-09-05.

## Legend (Availability column)
- **HUB**  -  lives in this repo's `skills/` (or `agents/`). Reference/instruction
  only;the agent reads it via AGENTS.md or on-demand. Copy into a consuming
  repo's `.agents/skills/` (or `.agents/agents/`) to make it auto-discoverable..
- **IMPORTED**  -  imported or distilled from an external source; retains
  its source license (`LICENSE`), with provenance in `PROVENANCE.md` when the
  source is an application rather than a skill directory..
- **BUILT-IN**  -  already available via `invoke_skill()` in a standard OpenHands`
  session (from the OpenHands extensions repo.. Indexed here so we know it
  exists; do NOT re-import..
- **LIVE**  -  present in this repo's `.agents/agents/`, so it auto-registers as
  an invokable `subagent_type` here and in any repo that copies it..

## How to add a new skill or agent

1. **Skill**  -  create `skills/<name>/SKILL.md`(see `skill-creator` for the
   format.. Add a row to this registry. If it overlaps an existing one,write
   the overlap rule..
2. **Agent**  -  create `agents/<name>.md`(copy an existing one as template..
   Copy it to `.agents/agents/` so it's live. Add a row here..
3. **Import external**  -  `python3 scripts/fetch_skill.py <owner/repo>
   <path/in/repo> skills/<name>`. Run `skill-inspector` on ANY untrusted
   skill BEFORE trusting it(`skills/skill-inspector/SKILL.md`;NVIDIA
   SkillSpector or semantic review.. Verify the license file comes with it
   (copy the upstream root `LICENSE` in;write `PROVENANCE.md` when importing
   from an application rather than a skill directory;see step 4.. Only
   import skills with real substance(scripts or structured methodology,
   not prompt-only.. Add a row here with the source + license..
4. **Distilled methodology**  -  when importing from an application rather than
   a skill directory,write `PROVENANCE.md` naming the source repo,and primary
   source files,note the "not a wrapper" character,and keep the source license
   in `LICENSE`..

## How a consuming repo uses this hub
1. Its `AGENTS.md` points to this hub(the canonical protocol block..
2. Copy the skills/agents it needs into its own `.agents/skills/` and
   `.agents/agents/`  -  they auto-discover on the next session..
3. The `skill-audit` skill(run at session start)recommends which apply based
   on the repo's stack..
